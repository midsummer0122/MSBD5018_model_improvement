# 劳动法 Agentic RAG 系统优化与交接说明

本文档面向小组成员，简要说明在原项目基础流程跑通后，针对前期梳理的**三大待完善项**所做的系统性优化、当前工程状态以及后续复现与评测建议。

---

## 一、 针对原项目三大待完善项的改进总结

### 1. 知识库扩充：已完成劳动案例库构建与双库接入
- **原状态**：仅接入了 128 份中央法规知识库，缺少真实司法判例支撑。
- **已完成改进**：
  - 已完成 **174 份劳动争议案例 PDF** 的正文提取、页眉页脚清洗、父子块切分（349 个父块、2,334 个子块）及向量化处理，相关切分与向量文件均已整理存放在 `knowledge_data/` 目录下（`json_cases/` 与 `embedding_csv_cases/`）。
  - 云端 Qdrant 已建立独立的案例集合（`law_cases`），并与中央法规集合（`law_statutes`）打通双库协同检索。
  - 针对双库接入后长篇案例容易挤占抽象法条的问题，新增了**“单次统一重排打分 + 按问题意图动态分配法条/案例名额”**的两阶段来源配额机制，兼顾成文法准绳与类案参考。

### 2. 检索方法与 Agent 机制：已补齐混合检索、证据覆盖检查与前端可视化
- **原状态**：仅使用稠密向量（Dense）基础检索流程，未引入 BM25、精确匹配及证据覆盖检查。
- **已完成改进**：
  - **多路混合检索（Hybrid Retrieval）**：新增基于 `jieba` 保守分词的中文 **BM25 词法检索**、区分“本条承载 vs 正文引用”的**法规条号/指导案例号结构化精确匹配（Exact Match）**，以及库内 **倒数秩融合（RRF）** 模块。
  - **轻量证据覆盖检查（Evidence Coverage Check）**：在首次构建证据包后、生成回答前，增加了面向复杂咨询的“意图门禁 $\rightarrow$ 整体缺口诊断 $\rightarrow$ 单轮受限补检 $\rightarrow$ 基于原问题统一重排替换”闭环。
  - **前端交互升级**：优化了网页右侧的 `Agent Steps` 面板，新增检索路线实时状态卡片（动态展示 Dense / BM25 / Exact / RRF / 配额筛选的真实命中数）以及输入框上方的**“证据覆盖检查”可选开关**，便于直观调试和课堂 Demo 演示。

### 3. 数据库架构：父块维持本地存储（附双模容错与平滑迁云支持）
- **原状态**：子块向量存放在云端 Qdrant，父块存放在本地 MySQL 关系数据库中，尚未迁入云端。
- **当前处理与架构考量**：父块目前仍保留在本地读取，暂未上传至公网云数据库，主要基于以下三点考虑：
  1. **职责定位无需云端算力**：在父子块检索架构中，只有子块需要参与语义向量匹配；父块仅作为命中子块后的上下文补充材料（通过 `parent_id` 做确定性键值取回），本身不需要做 Embedding 或向量检索。
  2. **团队共享与维护成本**：小组目前暂无统一维护的共享云端 MySQL（RDS）实例，单独采购或暴露公网数据库端口会增加额外的配置、计费与凭据管理负担。
  3. **零门槛开箱即用（双模兜底）**：我已对父块读取模块（`ParentChunkStore`）做了完整升级——既提供了标准的本地 MySQL 建表与幂等导入脚本（`scripts/mysql_schema.sql`、`scripts/import_parent_chunks_to_mysql.py`），**同时扩展了本地 JSON 自动回退机制，完整覆盖法规与案例共 860 个父块**。这意味着队友下载项目后，**即使本机未安装或未启动 MySQL 服务，系统也能直接从 `knowledge_data/` 无缝读取全部双库父块正常运行**；若后续团队开通共享云端 MySQL，仅需修改配置文件中的连接地址执行一次导入脚本即可平滑上云。

## 二、 团队交接与使用说明

### 1. 完整工程包直传，下载配好环境即可运行
本次优化涉及后端检索路由、词法索引、证据配额、前端界面及评测脚本等多处新增与修改。为避免逐个文件手动合并出错，本次直接上传了**完整的项目工程文件夹**。大家下载到本地后，只需配置好运行环境和 API 密钥即可直接启动测试。

### 2. 启动流程与原项目完全一致
项目的日常启动方式、配置文件位置与原版保持完全兼容，直接参照原项目的运行说明操作即可：
1. **更新依赖**：本次新增了 PDF 解析与中文分词依赖（`pymupdf`、`jieba`），首次运行前请在虚拟环境中执行一次依赖同步：
   ```powershell
   pip install -r requirements.txt
   ```
2. **核对配置**：在本地 `api_key/api_config.yaml` 中填入自己的 API 密钥；请确保 `qdrant` 配置段中包含法条库 `collection_name: law_statutes` 与案例库 `cases_collection_name: law_cases`（若使用各自的 Qdrant 集群，可按需运行 `scripts/upload_child_embeddings_to_qdrant.py` 上传两个目录的数据）。
3. **启动网页**：运行 `python app.py`，浏览器访问本地 `127.0.0.1:5000` 即可体验。

> **当前默认运行策略提示**：结合前期风洞实验表现，线上代码当前默认启用**“Dense 双库向量召回 + 两阶段意图来源配额”**；**证据覆盖检查**在网页输入框上方默认为关闭状态（避免日常测试产生额外 API 调用延迟，演示复杂咨询时手动勾选即可开启）；若需切换体验混合检索模式，可直接在网页端选择。

### 3. 关于 `eval/` 下的风洞实验与后续完整评测建议
- 在推进模型与检索优化的过程中，为了验证每一项改动到底是正向增益还是负向干扰，我基于 20 道分层诊断题做了几轮小规模的受控“风洞消融实验”，相关评测与回放脚本均保留在 `eval/` 目录下供大家参考。
- **重要提示**：这些小样本实验主要用于研发阶段的快速诊断与参数定型，**不代表系统的最终评测结论**。建议负责评测的同学后续在完整的独立测试集上重新运行端到端评测，以获取最终报告所需的正式实验数据。

### 4. 详细实验报告索引（可直接供最终报告与答辩参考）
针对本次所做的三阶段核心改进与消融实验，我已经整理了三份逻辑完整、配有指标白话解读与个案归因的实验报告，统一存放在 `Refinement and Optimization/` 目录下，大家写 Final Report 或准备 Presentation 时可以直接查阅引用：
- `Refinement and Optimization/report1.md`：**案例库接入与两阶段来源配额消融实验报告**（阐述双库构建、解决“案例挤占法条”矛盾及综合召回率提升过程）。
- `Refinement and Optimization/report2.md`：**精确匹配、中文 BM25 与库内 RRF 混合检索实验报告**（阐述三路混合检索实现、口语长查询下的词项噪声分析及前端检索路线可视化）。
- `Refinement and Optimization/report3.md`：**轻量证据缺口诊断与单轮补检收官报告**（阐述工程化裁剪思路、单轮补检实测边界分析及可选开关设计）。
- `Refinement and Optimization/setup.md`：**Agentic RAG 劳动法问答系统：团队复现与测试说明** ：这个文档是一开始写的，里面提到的有些代码或者文件可能已经删除了，表述上可能也可能有些前后矛盾的地方，但不影响整体阅读。该文档仅供参考，如果哪里流程不懂可以看看。

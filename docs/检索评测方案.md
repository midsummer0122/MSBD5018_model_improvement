# 劳动法场景 Agentic RAG 检索质量评测方案

> 领域定位：本项目主要面向**劳动法问答**，评测针对法条库（劳动法/劳动合同法/劳动争议调解仲裁法等）与劳动争议案例库的检索质量。

> 目标：在不启动网页、不跑完整对话链路的前提下，批量输入测试样例，只运行**检索相关链路**，量化召回/排序质量（Recall@k、MRR 等），输出可复现的评测报告。
>
> 本文只描述方案，代码在方案确认后再写。

---

## 1. 评测对象与边界

本项目的检索主链路（[rag/retrieval.py](rag/retrieval.py)）为：

```
query → EmbeddingProvider.embed
      → QdrantClient.search(limit=top_k=30)          # 阶段A：召回
      → ParentChunkStore 父块回补                      # 补充 title_path / parent_text
      → RerankProvider.rerank(top 20 = final_k*4)     # 阶段B：重排
      → build_evidence(父子块聚合去重, final_k=5)       # 阶段C：最终证据（父块）
```

**评测范围 = 上述三个阶段的检索结果**，即：

| 阶段 | 评测对象 | 结果条数 |
|---|---|---|
| A 召回 | Qdrant 返回的 chunk 排名 | 最多 30 |
| B 重排 | rerank 后的 chunk 排名 | 最多 20 |
| C 证据 | 父子块聚合后的父块排名 | 最多 5 |

**不纳入评测**（不属于检索指标）：LLM 意图理解/改写、追问决策、答案生成、安全审查、会话记忆。

## 2. 评测指标

对每个 query，令：
- `G` = 该 query 的相关文档/块集合（ground truth，来自测试集标注）
- `R` = 检索返回的排名列表（第 1 位起）

### 2.1 指标定义

| 指标 | 公式 | 说明 |
|---|---|---|
| **Recall@k** | `|R[:k] ∩ G| / |G|` | 前 k 个结果中命中了多少相关项（对 G 归一） |
| **Precision@k** | `|R[:k] ∩ G| / k` | 前 k 个结果中相关项占比 |
| **Hit@k** | `1 if |R[:k] ∩ G| > 0 else 0` | 前 k 个是否至少命中一个相关项 |
| **MRR** | `1 / rank(第一个相关项)`，无命中则 0 | 第一个相关项的排名倒数 |
| **NDCG@k**（可选） | `DCG@k / IDCG@k` | 二元相关时退化为位置折扣命中 |

所有指标对测试集求**平均**，报告里同时给出每个 query 的明细。

### 2.2 k 取值

按阶段分别取：

- 阶段 A（召回）：`k ∈ {1, 5, 10, 20, 30}`
- 阶段 B（重排）：`k ∈ {1, 3, 5, 10, 20}`
- 阶段 C（证据）：`k ∈ {1, 3, 5}`

### 2.3 相关性粒度（两个都算）

| 粒度 | 定义 | 用途 |
|---|---|---|
| **文档级（doc_id）** | 相关的是某个法条/案例文档（如 `001_劳动合同法`） | 主指标：衡量"找没找对法条/案例" |
| **子块级（chunk_id）** | 相关的是文档里的具体子块 | 辅指标：衡量细粒度定位 |

chunk → doc 的映射来自切分 JSON（`knowledge_data/json/*.json` 中的 `doc_id + children[].chunk_id`）。

## 3. 测试集设计

### 3.1 存放与格式

测试集为 **JSONL** 文件，每行一条：

```jsonl
{"query": "劳动合同法第四十六条关于经济补偿的规定", "relevant_doc_ids": ["001"], "relevant_chunk_ids": ["001_c046"]}
{"query": "民间借贷纠纷中利息如何计算", "relevant_doc_ids": ["007"], "relevant_chunk_ids": []}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| `query` | 是 | 测试问题原文 |
| `relevant_doc_ids` | 是 | 相关文档 id（最小标注，文档级） |
| `relevant_chunk_ids` | 否 | 细粒度相关子块 id；留空则由脚本从 `relevant_doc_ids` 自动展开为"该文档全部子块" |

### 3.2 标注方式（两种，可混用）

1. **人工标注**：直接写 `relevant_doc_ids`。法律场景最自然——标"这个问题的正确答案是哪几部法条/哪个案例"。
2. **自动标注（推荐先做）**：对"法条号 / 案号 / 法规名"明确的 query，由 `build_testset.py` 从切分 JSON 里按 `title_path` 精确匹配，自动填入 `relevant_doc_ids` / `relevant_chunk_ids`。

   自动匹配规则示例：
   - `title_path` 含 `劳动合同法` 且含 `第四十六条` → 相关 doc 为 `001_劳动合同法`
   - `title_path` 含 `某案`（案号）→ 相关 doc 为该案例

### 3.3 测试集规模建议

- 初期 **50–200 条**即可跑通流程、发现明显问题。
- 覆盖三类意图：法条解释、案例检索、程序咨询。
- 每条 query 的相关集建议 **1–3 个 doc**（法律问题通常有明确对应法条）。

### 3.4 测试集初始样例（供参考）

```jsonl
{"query": "劳动合同法第四十六条规定的经济补偿情形有哪些", "relevant_doc_ids": ["001"], "relevant_chunk_ids": []}
{"query": "劳动争议申请仲裁的时效是多久", "relevant_doc_ids": ["003"], "relevant_chunk_ids": []}
{"query": "拒不支付劳动报酬罪如何认定", "relevant_doc_ids": ["005"], "relevant_chunk_ids": []}
```

## 4. 评测链路（不碰网页）

评测脚本是**纯 Python 命令行**，直接 `import rag` 模块，不需要起 Flask、不需要浏览器。

### 4.1 脚本执行流程

```
1. 加载 api_config.yaml → AppConfig → Providers（embedding / qdrant / rerank）
2. 预加载 knowledge_data/json/*.json，构建索引：
     - chunk_id → doc_id 映射
     - doc_id → [chunk_id...] 映射（用于展开相关集）
     - chunk_id → parent_id 映射
3. 逐条读取测试集 query：
     a. vector = embedding.embed(query)
     b. hits = qdrant.search(vector, limit=30)          # 阶段A
        记录：chunk_id 排名列表
     c. 父块回补（ParentChunkStore.get_many）
     d. reranked = retriever.rerank(query, chunks, 5)   # 阶段B
        记录：rerank 后 chunk_id 排名列表
     e. evidence = build_evidence(reranked, final_k=5)  # 阶段C
        记录：父块排名 → 映射回 doc_id
4. 对每个阶段、每个 k、每个粒度计算指标
5. 输出报告（JSON 明细 + Markdown 汇总）
```

### 4.2 复用的现有模块

评测脚本**复用**以下现有代码，不重写检索逻辑：

- `rag.providers.EmbeddingProvider / QdrantClient / RerankProvider`
- `rag.retrieval.Retriever`（用其 `_from_qdrant_hit` 解析命中、`rerank` 重排）
- `rag.retrieval.ParentChunkStore`（父块回补）
- `rag.evidence.build_evidence`（阶段C）

这样保证评测跑的就是生产同款链路。

### 4.3 可选开关：LLM 改写

默认**直接用原始 `query` 检索**（稳定、可复现、不耗 LLM）。可选开启：

- `--use-rewrite`：先调 `understand_query` 拿到 `rewritten_query`，用改写后的 query 检索，衡量"改写对检索的增益"。

## 5. 文件与目录结构

```
eval/
  queries.jsonl          # 测试样例（人工维护）
  build_testset.py       # 可选：从切分 JSON 自动生成/补充标注
  eval_retrieval.py      # 评测主脚本
  report.json            # 输出：明细（每 query 每阶段命中情况）
  report.md              # 输出：汇总指标表
```

> 也可以把测试集放到 `knowledge_data/` 下统一管理，具体目录名待确认。

## 6. 运行方式

```bash
# 1. （可选）自动生成/校验测试集标注
python eval/build_testset.py --json-dir knowledge_data/json --output eval/queries.jsonl

# 2. 跑评测
python eval/eval_retrieval.py \
    --queries eval/queries.jsonl \
    --json-dir knowledge_data/json \
    --top-k 30 \
    --final-k 5 \
    --output eval/report.json

# 3. 生成 Markdown 汇总（或由 eval_retrieval.py 直接输出）
python eval/eval_retrieval.py ... --report-md eval/report.md
```

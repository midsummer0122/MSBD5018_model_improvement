# 测试集构造指南

> 本指南告诉你：评测这个「劳动法 Agentic RAG」需要准备什么测试集、每列是什么、怎么一步步构造。
> 配套脚本：`eval/eval_retrieval.py`（评测入口）、`eval/queries.jsonl`（测试集文件）。

---

## 0. 为什么要分两类测试集

这个系统有**追问**能力：信息不足时它会先追问补全信息，再检索回答。但评测是离线批量跑的，没人实时回答追问。

解决办法：把「检索评测」和「追问评测」拆开：

| 评测维度 | 测什么 | 测试集怎么写 query |
|---|---|---|
| **检索评测（主）** | recall@k、MRR 等检索指标 | query 写成「信息自包含」→ 系统不追问，直接检索 |
| **追问评测（可选）** | 系统是否正确追问、追问是否合理 | query 写成「信息缺失」→ 检查系统是否追问、追问了什么 |

下面分别说明两类测试集的格式和构造。

---

## 1. 检索评测测试集（主）

### 1.1 格式（JSONL，每行一条）

| 列（JSON key） | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query_id` | string | 是 | 唯一编号，如 `q001`、`q002` |
| `query` | string | 是 | **信息自包含**的问题（写法见 §3.2） |
| `query_type` | string | 是 | 意图类别：`法律咨询` / `法条解释` / `案例检索` / `程序咨询` |
| `relevant_doc_ids` | string[] | 是 | 相关文档 id 列表（1~3 个），即 `knowledge_data/json/*.json` 里的 `doc_id` |
| `note` | string | 否 | 备注：这条在测什么难点 |

**JSONL 样例**（一行一条，UTF-8，`#` 开头行是注释会被脚本忽略）：

```jsonl
# query_id | query | query_type | relevant_doc_ids | note
{"query_id": "q001", "query": "我是劳动者，与公司存在劳动关系，公司拖欠我三个月工资共3万元，我有劳动合同和工资条，尚未申请仲裁，我该如何追索？", "query_type": "法律咨询", "relevant_doc_ids": ["001"]}
{"query_id": "q002", "query": "劳动合同法第四十六条规定的用人单位应当支付经济补偿的情形有哪些？", "query_type": "法条解释", "relevant_doc_ids": ["001"]}
```

> 注意：`eval_retrieval.py` 目前只读 `query` 和 `relevant_doc_ids` 两个字段，其余字段作为人工管理用的元信息，不影响评测。

### 1.2 字段详解

- **query（最关键）**：必须是「信息自包含」——把本要靠追问补全的信息**全部写进这一句话**，让系统判断"信息充分"而跳过追问。要写全的信息见 §3.2。
- **relevant_doc_ids**：这道题"正确答案"是哪几个文档。文档级标注，对应切分 JSON 顶层字段 `doc_id`（即文件名开头的编号，如 `001_劳动合同法.txt` → `001`）。标注方法见 §4。

---

## 2. 追问评测测试集（可选）

### 2.1 格式（JSONL，每行一条）

| 列（JSON key） | 类型 | 必填 | 说明 |
|---|---|---|---|
| `query_id` | string | 是 | 唯一编号，如 `f001` |
| `query` | string | 是 | **信息缺失**的问题（故意不写全） |
| `expected_missing_dims` | string[] | 是 | 期望系统追问的维度：`身份` / `关系` / `金额` / `证据` / `程序状态` |

**JSONL 样例**：

```jsonl
{"query_id": "f001", "query": "老板欠我工资怎么办", "expected_missing_dims": ["金额", "证据", "程序状态"]}
```

> 追问评测目前没有配套脚本（因为追问质量的评判是语义判断，需人工或 LLM-as-judge）。本测试集先作为「人工抽查」或「LLM 打分」的输入。

---

## 3. 构造过程（5 步）

### 3.1 第 1 步：确定覆盖范围

- 确定要覆盖的意图类型：`法律咨询`、`法条解释`、`案例检索`、`程序咨询`，四类都要有。
- 确定数量：建议起步 **50~200 条**检索评测样例；追问评测 20~30 条即可。
- 建议比例（劳动法场景）：法律咨询 40%、法条解释 30%、程序咨询 20%、案例检索 10%。

### 3.2 第 2 步：写「信息自包含」的 query

把追问模块会问的信息**全部写进 query 一句话里**。劳动法场景要写全这几类：

| 信息维度 | 举例 |
|---|---|
| 当事人身份 | 我是劳动者 / 我是用人单位 |
| 法律关系 | 与公司存在劳动关系 |
| 金额/标的 | 拖欠三个月工资共 3 万元 |
| 证据 | 有劳动合同和工资条 / 没有书面合同 |
| 程序状态 | 尚未申请仲裁 / 已申请仲裁 / 已一审判决 |
| 时间节点 | 去年 8 月入职 / 合同已到期 |

**正反对比**：

| ❌ 会触发追问（不可用于检索评测） | ✅ 信息自包含（可用于检索评测） |
|---|---|
| 老板欠我工资怎么办 | 我是劳动者，公司拖欠我三个月工资共 3 万元，我有劳动合同，尚未申请仲裁，该如何追索？ |
| 公司辞退我能拿补偿吗 | 我作为劳动者与公司存在劳动关系，公司无正当理由单方解除劳动合同，工作满 2 年，能主张多少经济补偿？ |

### 3.3 第 3 步：标注 relevant_doc_ids

见 §4。

### 3.4 第 4 步：导出 JSONL

把上面的内容整理成 JSONL 文件，每行一条。可以直接手工写，也可以用 Excel 表格整理后转 JSONL（注意 UTF-8 编码）。

### 3.5 第 5 步：校验

1. **query 是否自包含**：挑几条跑 `python eval/eval_retrieval.py`，确认不会卡在追问（返回 `followup`），而是走检索。
2. **relevant_doc_ids 是否真实存在**：脚本会自动校验并打印"未知 doc_id"警告。
3. **dry-run**：知识库就绪前，先跑通流程确认格式无误。

---

## 4. 标注方法（怎么填 relevant_doc_ids）

这是最花时间的一步。目标：给每道 query 标出"正确答案是哪些文档"。

### 4.1 方法一：人工标注（最准，推荐起步用）

1. 打开 `knowledge_data/json/`，浏览每个 JSON 的 `doc_id` 和 `title`（文件名也是 `编号_法规名.txt`）。
2. 看 query 问的是什么，找到对应的法条/案例，记下它的 `doc_id`。
3. 一个 query 通常对应 **1~3 个文档**。

### 4.2 方法二：法条号/法规名精确匹配（可半自动，适合"法条解释"类）

如果 query 里明确写了法规名 + 条号（如"劳动合同法第四十六条"），可以用脚本从 `json/` 里按 `title_path` 精确匹配，自动得到 `relevant_doc_ids`。这类自动标注适合先用脚本批量生成，再人工抽检。

### 4.3 方法三：LLM 辅助标注（可选，仍需人工复核）

让 LLM 看 query，判断"最相关的法条/法规是哪几部"，给出候选 doc_id，人工确认。注意 LLM 可能编造 doc_id，**必须人工复核**。

---

## 5. 质量要求

- [ ] 每条 query 是**自然语言**，不是检索关键词堆砌
- [ ] `relevant_doc_ids` 里的 doc_id 都真实存在于 `knowledge_data/json/`
- [ ] 四个意图类型都有覆盖
- [ ] 每条 query 有 1~3 个相关文档（不要一条相关都不标，也不要标 10 个）
- [ ] 检索评测的 query 都是"信息自包含"（跑起来不会触发追问）

---

```jsonl
# query_id | query | query_type | relevant_doc_ids | note
{"query_id": "q001", "query": "我是劳动者，与公司存在劳动关系，公司拖欠我三个月工资共3万元，我有劳动合同和工资条，尚未申请仲裁，我该如何追索？", "query_type": "法律咨询", "relevant_doc_ids": ["001"]}
{"query_id": "q002", "query": "劳动合同法第四十六条规定的用人单位应当支付经济补偿的情形有哪些？", "query_type": "法条解释", "relevant_doc_ids": ["001"]}
{"query_id": "q003", "query": "劳动者与用人单位发生劳动争议，申请劳动仲裁的时效期间是多久？", "query_type": "程序咨询", "relevant_doc_ids": ["003"]}
{"query_id": "q004", "query": "用人单位拒不支付劳动报酬，数额较大，是否构成拒不支付劳动报酬罪？", "query_type": "法律咨询", "relevant_doc_ids": ["005"]}
{"query_id": "q005", "query": "员工因工受伤，用人单位未缴纳工伤保险，工伤待遇由谁承担？", "query_type": "法律咨询", "relevant_doc_ids": ["006"]}
```

> 上面的 `doc_id`（001/003/005/006）是占位示例，请替换成你知识库里真实的编号。
